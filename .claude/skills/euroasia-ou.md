# 欧亚盘玩法（结算按欧盘/亚盘）

> **定位**：真实投注结算按欧盘/亚盘（365终指亚盘 / 99家欧赔）。竞彩官方只做①场次选择②盘口参考。
> **定调**：用户2026-08-30确认——"结算按欧盘结算，可以上盘口和大小球，上多特-1.5而不是竞彩让-1，竞彩是场次选择和盘口参考"。

---

## 一、机制金字塔

```
竞彩(sporttery)        = 过滤网 + 参照系
    │ 挑开哪些场次
    │ 看竞彩怎么让球(整数档)
    ▼
欧亚盘(365/99家)       = 真实下注与结算
    │ 亚盘让球(平半~两球半)
    │ 大小球(大/小2.5、3.0、3.5...)
    │ 欧赔独赢(胜平负)
    ▼
数据源(okooo)          = 365终指 + 99家欧赔 + 近况亚盘战绩
```

- 单场可投（不必2串1）
- 下注记号：直接写"多特-1.5 @1.90"（亚盘），不是竞彩"让球胜@1.79"

## 一.5、欧亚错配批量扫描（2026-08-30能力+口径修正）

**数据源（两个都可靠，已打通）：**
1. **竞彩当日全量 API** `getMatchCalculatorV1.qry?channel=c&poolCode=hhad,had` → 今日全部主流场次 + 竞彩让球盘 goalLine + spf（`data/okooo_cache/jc_today_full.json`）
2. **okooo 历史页缓存** `data/okooo_cache/<okoooid>.json` → 每场**本场亚盘**（homeRecent[0].handicap 中文盘）+ 99家欧赔 + 365终指 + 世界排名 + 近5亚盘赢盘率

**口径（关键！）统一用「客队被让深度」：**
- 竞彩 goalLine "+1" = 主受让1 = 客让1 → away_depth +1；"-1" = 主让1 → away_depth -1（**竞彩 goalLine 数值直接就是客让深度**）
- okooo 中文盘（主队视角）：受一球=客让1=+1；一球=主让1=-1；球半=-1.5；平手=0；平手/半球=-0.25

**gap = 亚盘让客 − 竞彩让客**（away_depth 口径）
- gap **负且大**（亚盘让客比竞彩深，如亚盘-1.5 vs 竞彩-1 → gap-0.5）→ 市场更看好客队/主队 → **竞彩低估主队 → 上主队亚盘**
- gap **正且大**（竞彩让-1 vs 亚盘平手/平半 → gap+0.75~1.0）→ **竞彩高估主队 → 让-1陷阱 → 反向买客队受让**

**让-1陷阱反向是本批最强信号**（竞彩让-1 但亚盘只平手~平半，市场认为主队让不起1球）：买客队受让（+0.25~+0.5）。风险源：主队主场大胜（受让+1的天敌）。

**⚠️ 重要过滤（2026-08-30 加）**：让-1陷阱反向**先看客队近5亚盘赢盘率**。若客队 0/5（近5场全输盘）——那是陷阱中的陷阱，客队太弱，即使竞彩高估主队、客队也大概率输 → **排除**。只有客队有赢盘能力（≥2/5）或强队身份才买。
- 实例：塞尔塔vs毕尔巴鄂 / 拉科vs巴伦西亚 / 奥格斯堡vs沙尔克 → 客队全部 0/5 → 全部跳过
- 摩纳哥vs马赛：马赛 2/5 + 强队 → 买马赛平手受让 ✅

**深盘错配（低估强客队）**：竞彩只让-1 但亚盘让客-1.5（如特温特/阿尔克马/多特）→ 竞彩低估强队 → 上强队-1.5。佐证：世界排名悬殊 + 99家超热门（<1.4）+ 对手联赛垫底。风险：强队客场状态一般时穿盘失败。

**⚠️ 与 M4 模型的冲突警示（2026-08-30 发现）**：
- **M4 让-1陷阱反向**（反买客队受让）在模型档案里是 **0胜全败** 记录（热刺-2穿盘/帕梅拉斯-1 3:0/达伽马-1让平，全部主队方向）
- 模型教训写明：「让球-1的让负是陷阱，主队穿盘才是价值」
- **欧亚错配的"竞彩-1 vs 亚盘浅" 与 M4 的"让-1陷阱反向"是同一批场次、相反方向 → 直接冲突**
- **处置**：此方向只做**虚拟注**验证（vb-042~048 正在检验），**不押真钱**。若虚拟全赢 → M4 需翻案；若再败 → 坐实 M4 教训，欧亚错配的「让-1陷阱反买客队」子逻辑废除
- 实盘决策以 **P2a_gl1（EV172.6%）为准**，今日0命中 → 实盘空仓

参考实现：`tools/scan_now_tmp.py`（已清理，逻辑见上）。2026-08-30 周日盘实例：

## 二、数据抓取

### 1. 竞彩列表（场次选择）
```bash
node tools/okooo_jingcai.js --force   # 今日竞彩 → 输出 {num, league, home, away, matchId, 竞彩赔率, 让球}
```

### 2. 单场欧亚盘详情（亚盘让球 + 99家欧赔 + 近况亚盘战绩）
```bash
node tools/okooo_scraper.js match <matchId> --force
```
返回：
- **本场亚盘**：`homeRecent[0]` 的 `handicap`（如"球半"）`handicapOdds`（如1.90）
- **99家欧赔**：`odds99Home/odds99Draw/odds99Away`
- 365终指：`odds365`
- 双方近10场亚盘战绩（判断状态：赢/输/走）

### 3. 大小球（从欧赔反推）
```bash
python tools/ou_calc.py --odds 1.35 5.45 7.18 --team "阿尔克马 vs 前进之鹰"
python tools/ou_all.py --date 2026-08-29   # 批量今日全部 → data/ou/ou_2026-08-29.json
```
原理：99家欧赔→去水→公平胜平负概率 → 反推 λ/μ（期望进球，网格搜索）→ Poisson/Dixon-Coles 算 大/小 2.5/3.0/3.5 概率与公平赔率。

### 4. 虚拟注自动结算
```bash
node tools/vb_settle.js          # 结算所有已开赛在途虚拟注（亚盘/大小球）
node tools/vb_settle.js list     # 只列在途
```
比分开赛后再运行，自动用 sporttery getFixedBonusV1 查比分，按亚盘让球线（-1.5/-1.25/+0.5等.25/.75/.5盘）或大小球线判定 win/loss/push。比分未出→待定不写盘。

⚠️ **结算语义（重要）**：
- **亚盘让球**：走盘=push(void)。pick文本必须含显式让球线（如 `多特 -1.5`、`马尔默 +0.5`），工具靠 `[+-]\d+(\.\d{1,2})` 提取。
- **大小球**：总分恰=线=push。pick含 `大2.5`/`小3.0` 格式。
- **竞彩让球(legacy)**：让平=**输**（不是走盘），且需用 `b.goalLine` + sporttery HHAD 判定，不能从 pick 提取线。旧虚拟注(vb-016~026)属此类，已结算不回改。

## 三、玩法逻辑：亚盘深度 vs 竞彩让球错配

**核心：亚盘盘口深度（市场定价） vs 竞彩让球需求（固定整数档）的 gap = 定价偏差**

| 场景 | 判断 | 下注 |
|------|------|------|
| 亚盘深（球半1.5）但竞彩只让-1 | 市场更看好主队，竞彩低估 | 上主队亚盘让球（如主-1.5）|
| 亚盘浅（平半0.25）但竞彩让-1 | 市场接近五五开，竞彩高估主队 | 不追让球胜 / 反向 |
| 亚盘与竞彩匹配 | 无错配 | 空仓 |

**结合欧赔去水偏差验证**：99家去水概率 vs 竞彩去水概率，偏差>3pp才算显著定价错误。

## 四、大小球玩法

- 期望总进球 = λ+μ（从欧赔反推）
- λ+μ ≥ 3.0 → 倾向大球；λ+μ ≤ 2.5 → 倾向小球
- 大球价值：过大2.5/3.0/3.5 时，找**大球概率 vs 盘口隐含**偏差
- 大小球独立于胜平负：强让球主队往往大球（需求净胜2球）

---

## 五、纪律（优先级最高）

1. **竞彩只做过滤**：不在竞彩规则里下注（除非竞彩真正有优势）
2. **结算口径统一**：记录就用365/99家赔率（okooo抓的口径）
3. **R1-R6 仍适用**：投前验证 matchId、时间窗口≥30分钟、单笔仓位
4. **连输2单降档**：单笔上限降到当前阶段最低档（起步期=2%）
5. **季初xG不用于决策**：样本<5场时只做参考（见 [[xg-quant]]）
6. **变盘记录**：下单前必须记录该场已出现的赔率变动次数
