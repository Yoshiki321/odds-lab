# 竞彩助手

竞彩网(sporttery.cn) 官方数据抓取与分析工具。

## 启动

```bash
node scraper.js all            # 赔率 + 近30天历史 + 联赛 + 比分直播
node scraper.js odds           # 即时赔率快照
node scraper.js history [date] # 历史赛果(默认2015-01-01至今)
node scraper.js league         # 联赛资料
node scraper.js support [date] # 支持比例
node scraper.js ctzc [N]       # 传统足彩最近N期
node scraper.js live           # 比分直播
```

## 口令（用户 2026-09-06；2026-09-09 指向 v2）

用户只说 **「更新」**（或「更新网站」）= 立刻执行，**不问不解释流程**：

1. `cd app && npx tsx tools/refresh.ts`（抓竞彩当日盘 → 合入 PG → 抓 support/odds_history/base_rates → 重算 v2.0 评分 → 拉已开奖赛果）
2. 本轮若改过 `app/src/server/`：`node tools/restart_server.cjs 9000`；只改了 `app/public/` 不用重启
3. 回复：抓了几场、评分时间、信息源有无报错、实单+资金。网页只读新文件，用户刷新即可看到

失败就报信息源错误，禁止空口说已更新。

> ⚠️ 旧 JS 引擎已退役：`tools/refresh_scores.cjs` / `tools/score_sat_full.cjs` 仅存档。v2.0 评分见 `app/tools/score.ts`（TS，权重 22/12/22/12/22/10，严格EV，档位 58/48/40/30）。

## 技能

- `/jingcai-scraper` — 竞彩网 API 接口速查与数据抓取。所有接口的完整参数说明、返回数据结构、调用示例，以及快速查询技巧。
- `/backtest-learning` — 历史回测自我学习。翻读 data/history/football/ 的历史赛果，模拟2串1玩法从1000到10000，反复复盘沉淀策略到skill。
- `/xg-quant` — xG 量化分析：Understat xG → Dixon-Coles → +EV → 凯利（季初样本不足，决策未启用）。
- `/euroasia-ou` — 欧亚盘玩法：竞彩只做场次选择+盘口参考，结算按欧盘/亚盘。抓亚盘让球 + 大小球推导，上盘口/大小球/单场可投。

## 评分中枢（一切围绕评分构建）

**评分是系统的唯一中轴。** 运维、升级、实单三条线都围着 `data/scores/<date>.json` 转。网页只展示分数，不计算分数。

### 铁律：分析盘口必须更新平台数据

只要开始分析盘口（扫盘、临场、对比欧亚、给场次打分），必须先把平台数据刷到最新：

```bash
node tools/refresh_scores.cjs          # 抓竞彩当日盘 → 合入 data/today → 重算 data/scores
```

不刷新就分析 = 用旧盘口决策。刷新失败（sporttery/okooo 空页、405、JSON 解析失败）必须当场上报信息源错误，不得假装有分。

### 1. 运维：定时更新网页评分 + 上报信息源错误

- **谁打分**：本会话 LLM。由 **CronCreate durable 循环** 触发，不是网页 `setInterval`，不是 server.js 自己 spawn 打分。
- **做什么**：跑 `app/tools/refresh.ts`（v2，npx tsx）→ 合入 PG → 重算 v2.0 评分。看板每 2 分钟只读 `/api/day` 把新分数画出来（v2 分数写 PG scores 表，`data/scores_*.json` 已不是主读源）。
- **报错**：信息源挂了（空场次、接口失败、okooo 空缓存）写 `data/scores/_status.json`，回复里点名源和错误，网页红条同步显示。
- **不要**：用 JS 脚本代替 LLM 思考；不要在刷新评分任务里结算/下单（那是 13:03/23:07 的事）。

### 2. 升级：彻底围绕评分精准度自我升级

- 每次结算、虚拟注揭晓、错杀/漏抓，都要问：六维里哪一维打偏了？
- 结论写进 `data/betting/scoring-system.md` 版本号 + 当日日记（自我升级已并入日记，规则/错误账固化在 `data/diary/scoring-upgrade.md|json`），下一轮 `app/tools/score.ts` 吃新规则。
- 自我升级页只服务评分准确度，不散修别的。

### 3. 实单：围绕评分下注，检测评分、给自己加任务

- 仓位跟分数走（v2.0 档位）：≥58 加注（顶格10%）、48-57 实单（5%）、40-47 只虚拟、其余放弃。模型命中是加分项，分数冲突时分数优先。
- 实单是活体测验：赢了说明这套信息值成立，输了必须给自己布置复盘任务（哪一维虚高、哪路降水没吃到）。
- 不把“感觉”压过分数；要把“为什么分数没拦住这单”写成下一版规则。

### 结算机制（欧亚盘定调，用户2026-08-30确认）
**结算按欧盘/亚盘赔率**，竞彩官方只做两件事：
1. **场次选择**：竞彩开哪些场次 → 从那里挑值得投的
2. **盘口参考**：竞彩让球盘/胜平负 用于对比欧亚盘找定价偏差

**可投形式（不限于竞彩规则）**：
- ✅ **单场**（不必2串1）
- ✅ **亚盘让球**（上盘口，如"多特-1.5"球半）
- ✅ **大小球**（欧盘大2.5/小2.5等任何盘口）
- 结算盘口 = 365终指亚盘 / 99家欧赔（okooo扫码数据）
- 下注时直接按目标欧亚盘口记录（如"多特-1.5 @1.90"），不是竞彩"让球胜@1.79"

2. **一次性任务只用于固定节点覆盖不到的时点**：如深夜场次日凌晨才踢完（23:07关盘时未终场，需额外设 00:xx 一次性专结）；或某场特定临场变盘扫描（如9-02 16:33 那类）。
3. **一次性任务用 durable 写盘**（跨重启存活），除非确认会话会全程开着。
4. **time 错开整点/半点**：选 03/07/33 这类分钟，避免撞点。
5. **幂等守卫（防重复入账）**：任何结算类任务触发后，先巡检在途注单状态——已 `settled` 或官方 `matchResultList` 有终场判定的**一律跳过**；官方未终场（只有 sectionsNo999 实时比分）**绝不结算**。重复触发=白扫一遍，绝不重算账。
6. **7天过期**：durable 循环任务系统自动 7 天过期，需在到期前重建；下个会话先 `CronList` 核对。
7. **买不买自主判断不询问**：定时触发的任务也照此纪律，执行后汇报账态与信号即可。
