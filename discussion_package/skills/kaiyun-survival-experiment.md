# 开云体育 100 元生存实验（操作手册）

> 本 skill 是唯一操作规范。与旧文档冲突时以本 skill 为准；本 skill 未写的一律按"不确定→不操作"处理。

## 0. 铁律（最高优先级，逐条不可破）

1. **只准开一个网页**：全程只使用自动化 Edge（`--remote-debugging-port=9333`，profile `D:\web\AICamera\竞彩助手\.edge-auto`）里的**同一张标签页**。禁止开新标签、新窗口、其它浏览器；发现多页立即收敛为一页。所有操作都在这一个页上完成。
2. **不碰凭据**：登录由用户在该页亲手完成；用户 2026-11-19 批准后可把会话头保存到 `runtime/api_credentials.json`（权限收紧、值不回显），引擎据此脱离页面走接口。凭据失效就重新登录并保存，不绕过。
3. **生效风险参数**（用户 2026-11-19 确认，**不得自调**）：预算 100 元 · 单注 ≤2 元 · 未结敞口 ≤5 元 · 当日风险 ≤5 元 · 累计亏损 ≤20 元。不充值、不提现、不转账、不借贷、不追损、不马丁格尔。
   - **授权覆盖记录（只作历史，不作生效规则）**：2026-11-19 曾先后出现「单注 1→2」「未结 3→5」「额度上限取消」「单注=余额10%」等口头变更，并在当晚报废。其中 20 元湖人单、7 元老虎单均属**越界执行**，记录在案，不计为合规样本。
   - **恢复条款**：任何额度调整必须书面写明生效范围与期限，且当晚不得再次变更；口头"全权/取消上限"不作为长期规则。
4. **真实下单需批准**：默认只观察+记录。下单必须在用户明确批准后执行；每次一单，提交后立刻停下报告，不自动追加第二单。
   - **补充（2026-11-19 审计后生效）**：滚球（LIVE）一律**只下虚拟单**，累计 ≥30 单再做审计；真实滚球单暂停。
5. **不编造**：概率未知就写未知；赔率是观察价不是成交价；未找到费用表就不能断言无手续费；未找到禁止条款也不等于自动化已获许可。错过就记未执行，绝不补造。
6. **规则不明不下单**：玩法结算、截止、取消、费用任一项不明确 → 不下。异常一律先停再查。
7. **账本隔离**：模拟写 `simulation.json`，真实写 `ledger.json`（真实条目只允许用户批准的 `EXP100-REAL-*`）。两者不得混写。

## 0.5 算法门槛（2026-11-19 审计后新增）

- **开云实单只做**：竞彩有评分（≥48）· 欧赔齐全 · EV>0。三条缺一不下。
- 依据：项目 247 场审计，EV>0 组 ROI +39%，无欧赔组 −16% 最差；今晚 6 单全部落在“无评分、无欧赔、小联赛滚球”这一类。
- **禁止**以“低抽水”为下注理由：1.83/1.85 抽水约 8.7%、1.80/1.80 约 11%，在此水位需 54%~56% 胜率才保本。
- 注额：无优势时凯利 f*=0 → 不注；有 EV 才按既有注额规则下。
- **“回本”不是目标**：不得因亏损加大注额；额度变更当晚不得超过一次。

## 2. 时间与时区

- 一律 Asia/Shanghai(+08:00)；调度用绝对毫秒，报告显示北京时间并标 `+08:00`。
- 比赛日 = 当日 12:00 至次日 12:00；跨午夜场按绝对时间排，不按日期字符串。
- 早间扫盘：每天 **09:00**（可改 08:00/12:00，需用户指令）。
- 临场复核：**开赛前 30 分钟**触发；可执行窗 = `[计划时刻, 计划时刻+5分钟]`。早于计划时刻不执行（禁止提前到 T-40），超过 +5 分钟、已开赛、数据过期 → 放弃并记录，不补单。

## 3. 早间扫盘（09:00，只观察不下单）

1. 读体育页，收集范围内场次：主盘 = 全场独赢 / 全场让球 / 全场大小；长尾盘（波胆/角球/15分钟）排除；滚球不做。
2. 分级：**一类** = 欧冠、欧国联、欧联杯、英超、西甲、意甲、德甲、法甲；**二类** = 英冠、德乙、西乙、葡超、荷甲、巴甲、美职、土超；**三类** = 空（需用户逐项放开）。先一类，无合适再看二类，都没有就空仓。
3. 排序：开赛时间升序，同时间主队名 Unicode 码点升序。**不限流，全部纳入**；若必须限流，逐个记"未处理/需后续处理"，不许静默丢场。
4. 每场记录：联赛、双方、比赛ID、开赛时间(+08:00)、分级、可观察盘口/赔率、观察时间、数据来源与缺失、状态（候选/暂不考虑/排除/待核实）、理由。
5. 产出：`sweep/plan_<date>.json` + `sweep/morning_<date>.md`，并为每个候选排临场复核时间。

## 4. 临场复核（计划时刻触发）

复核清单（缺项即放弃并记原因）：实际时间/距开赛分钟；赛事身份与最新开赛时间；最新盘口+赔率+来源+时间；与早间变化（多快照并存）；首发/伤停（可靠才写，否则未知）；余额/未结/当日/累计风险；规则与截止；最终决定（买入/放弃/待核实）+理由。

- 早间选中 ≠ 临场必买；盘口变化只是信息，不是必胜信号。
- 同一赛事只允许一个临场任务，执行过就拒绝重复（`claimTask`）。

## 5. 下单前五门禁（任一不过不下）

1. 规则明确（该玩法结算/截止/取消/费用）
2. 赔率与盘口在提交前复核且一致（变了就重判）
3. 风险四算全过：单注≤2、未结+新≤3、当日+新≤5、累计亏+敞口≤20
4. 赛事未截止、未开赛
5. 用户已批准自动执行（否则只记录建议）

提交后：只提交一次 → 以平台回执为准记录订单号/实际赔率/金额/状态 → 立即停下报告 → 结果不明先查订单，绝不重复提交。

## 7. 定时机制

- 守护进程：`node tools/ky_daemon.cjs`（常驻；每 30s 检查一次）
  - 09:00±60s：调 API 引擎全量扫盘（2500+场，不点页面）
  - 临场任务：在 `[计划, +5min]` 内用 API 读实时盘口并记录（不下单）
  - 凭据从当前页面请求头临时捕获，仅内存不落盘；失效记失败
  - 单页保证：复用唯一页，多余页关闭
  - 状态：`data/experiment_survival_100/runtime/daemon_state.json`，日志 `runtime/daemon.log`
- 开机自启：Windows 任务计划 `KYDaemon`（用户登录时启动，隐藏窗口）
- 重启后：读 state 判断今日扫盘是否已做；未做且在窗口内则补跑，超窗记 missed，**不伪造**

## 8. 收尾与报告

每次运行都要留可核对痕迹：计划时间、实际执行时间、成功/失败、失败原因。日报包含：各类场次数量、候选/排除名单及理由、临场任务时间、数据缺失与异常、未结与余额。

## 9. 结算核对铁律（2026-11-19 事故后立）

- 对账必须三源交叉：①订单列表 `getOrderListPB` 的 `betResult`（3 输 / 4 赢 / 5 赢半）；②未结数 `countUnsettleTickets`；③余额 `/yewu12/user/amount`。任何一项对不上，不下结论，先问用户 APP 里的状态。
- 订单列表会漏单（2026-11-19 鳄鱼v老虎 7 元：APP 可见、未结数含它、余额已扣，列表所有筛选组合都查不到）。列表查不到 ≠ 退单。
- 退单判定：只有余额回到下注前才算退单；余额已扣但列表查不到 = 在途（接口漏单），结算后看余额变化或用户 APP 补录。
- 未结数只能和余额、列表一起用，不能单独作结算依据；比赛详情接口（结束即空）不能用来判断在途。
- 订单号回执（16 位）与列表 betNo（15 位）不一致，账本用 betNo，禁止按回执号去重或匹配。
- 汇报结果前必须有 `betResult` 或余额变化作依据，没有就写“待确认”，不许推测。
- 下注前必须复核盘口线与赔率；线位变动（如 -9.5→-11.5）或赔率变动>0.10，视为新决策重新判断。
- 每笔记录：`oddsValues`、`marketValues`、`betAmount`、`betResult`、派彩、余额快照；对账公式 `期初 − 本金 + 派彩 = 当前余额` 必须平。
