# 定时任务规则（CronCreate 动态定时）

> 用户 2026-09-01 定调：后台 sleep/完成唤醒跨时段失效（窗口或进程重启即丢）→ 改用 **CronCreate**，任务定义持久化写盘。

## 为什么
- 后台 sleep + 完成通知：只在**同一窗口持续打开**时有效；窗口/进程重启或跨长时段就丢（已验证失效）。
- CronCreate durable：任务写 `.claude/scheduled_tasks.json`，**定义跨重启保留**；会话关闭后靠下次打开会话恢复/补跑，实时性依赖 REPL 进程在场。
- 结论：**用 CronCreate 做唤起，不用后台 sleep**。

## 设定时纪律（骨架+补充）
1. **固定节点是主轴**（每日13:03/23:07循环），一次性只补固定节点覆盖不到的空档，不重复做同样的活。
2. **一次性用于**：深夜场次日凌晨才踢完（23:07未终场→额外设 00:xx 专结）；某场特定临场变盘扫描（如 9-02 16:33 P2a三候选）。
3. 一次性任务用 **durable** 写盘（除非确认会话全程开着）。
4. **time 错开整点/半点**（03/07/33 等）。
5. **幂等守卫**：结算类任务触发后先巡检在途——已 settled 或官方 matchResultList 有终场判定→跳过；官方未终场（只有 sectionsNo999）→绝不结算。重复触发=白扫一遍，不重算账。
6. **7天过期**：durable 循环 7 天自动过期，到期前重建；下个会话先 `CronList` 核对。
7. 定时触发也**自主判断不询问**，执行后汇报账态+信号。
