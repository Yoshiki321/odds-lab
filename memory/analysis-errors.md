# 自我升级机制

## 架构

```
memory/
├── mistakes/
│   ├── mistake-001.md    # 虚构赛果（AC米兰2-0博洛尼亚）
│   ├── mistake-002.md    # 赛季混淆（切尔西2-1热刺）
│   └── index.md           # 错误索引，每次新增错误后更新
├── analysis-errors.md     # 分析错误类型分类与应对
└── pre-bet-checklist.md   # 投注前必须执行的核查清单
```

## 运行机制

### 1. 每次新会话 → 加载错误索引
启动时先读 `mistakes/index.md`，知道所有已犯错误，避免再犯。

### 2. 每次投注前 → 执行核查清单
`pre-bet-checklist.md` 中的每一条必须逐一核对，确保不遗漏。

### 3. 发现错误 → 记录三要素
新错误必须记录：
- **错误的描述**：事实陈述
- **根本原因**：为什么发生（技术原因 + 认知偏差）
- **如何避免**：具体可操作的规则

### 4. 每轮复盘 → 做回顾

### 5. 错误升级（最重要的机制）
如果同一个错误 **再次发生**，该错误升级为"系统级规则"写入 CLAUDE.md 或 memory，并对该规则增加惩罚性检查步骤。

## 错误类型分类（防复发策略）

| 类型 | 示例 | 防御策略 |
|------|------|----------|
| **虚构赛果** | 搜索引擎生成假比分 | 赛果一律官方API；外部信息只做背景 |
| **赛季混淆** | 上赛季数据当本赛季 | 赛季边界检查（R2） |
| **matchId错配** | 支持率数据的ID当投注ID | 投注前验证matchId（R3） |
| **虚假状态** | 休赛期"状态好" | 只有官方标记Played才算已赛 |
| **分析维度不足** | 只看赔率快照，未追踪赔率变化/冷门/体力/变盘 | 8维分析框架（见strategy.md v2） |

## 复盘记录（每次结算/每轮投注后做）

> 每个投注周期结算后，把"实际结果 vs 我当时的分析"对照，提炼要保留/要修正的认知。

### 2026-08-24 复盘 — 投注前的盲点

复盘时发现4个当时未考虑的问题，事后用官方数据验证：

| # | 问题 | 我当时的做法 | 验证结果 | 教训 |
|---|------|------------|---------|------|
| 1 | 赔率变化分析 | ❌ 只看一张快照 | 巴萨客胜1.22→1.20持续下调，其余无变化 | 必须追踪开盘到临场走势 |
| 2 | 博冷门 | ❌ 全投热门 | 巴萨91%大众支持，大热场次 | 冷门价值需要主动评估 |
| 3 | 体力/伤停 | ⚠️ 只查了赛程场次 | 意甲/英超两队均首秀；巴萨8-13欧超后8-24+8-28密集 | 赛程密度+关键伤停必查 |
| 4 | 变盘 | ❌ 未监控 | 唯一变盘信号是巴萨客胜持续走低=热度信号 | 5%以上赔率变化必须记录并解释 |

**影响：** 本轮3单中，#1(巴萨×切尔西)因巴萨过热成为最高风险串。这是教训——**大热低赔在赛季初是效率最差的投注**。已固化为8维分析框架，今后每场必查。
