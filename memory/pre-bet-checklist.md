# 投注前核查清单（必做）

## 第一阶段：数据来源验证

- [ ] **1. 赛果/状态 = 只来自官方API**
  - 不看外部搜索的"近期状态"作为投注依据
  - 外部搜索只用于：伤病、转会、战术背景，不用于比分/赛果
  - 来源：`data/league/leagues.json`（标记 Played 的才算已赛）
  - 来源：`data/history/football/`（新赛季日期范围内的才算有效）

- [ ] **2. 赛季确认**
  - 当前是 **2026-27赛季**（2026年8月开始）
  - 2026年5月及之前的比赛是上赛季，不计入"当前状态"
  - 确认方法：查看联赛数据中该队2026/2027赛季赛程的 Played 场次

- [ ] **3. 赔率与实际场次匹配**
  - 每笔投注的 matchId 必须在 `data/odds/_latest/football_all.json` 中实际存在
  - 确认 matchId 对应的 matchNumStr、主客队与投注档案一致
  - 这是之前犯过的错误：误把支持率数据中的 matchId 当成了投注场次

## 第二阶段：投注合规检查

- [ ] **4. 赛前投注确认**
  - 当前时间 < 投注场次的开赛时间（北京时间）
  - 检查 matchStatus 是否为 "Selling"
  - 永不投已开赛或即将在30分钟内开赛的场次

- [ ] **5. 资金纪律检查（目标¥10000版）**
  - 起步期(500~1000)：单笔 ≤ 现金的 5%
  - 累计当日投注 ≤ 当前现金的 20%
  - 连输2单后单笔上限降到当前阶段最低档

- [ ] **6. 串关检查**
  - 仅做2串1（不做3串及以上）
  - 每腿只选一个结果（不做双选）

## 第三阶段：投注后验证

- [ ] **7. 投注档案验证**
  - 写入 bet 档案后，回读并验证每个 matchId 与场次信息一致
  - 验证赔率与实际数据一致

- [ ] **8. 台账更新验证**
  - 投注后现金减少量 = 投注金额
  - current cash = startBankroll - totalStaked + totalReturned
