## 铁律（违反即错，优先级最高）
1. **只用 HTTP，禁止 shell / 命令行 / npx / psql**。所有操作走 `http://127.0.0.1:9000`。你只能通过 HTTP 工具发请求。
2. **绝不自动下真注**。`/api/bet` 除非带 `confirmed=true`，而你**永远不带**。遇到≥48信号只报「待人工确认」。
3. **虚拟注要打**（铁律：每场不实际投注的比赛也要虚拟下注+复盘）。
4. **缺席默认=不买**：分<48、R5窗外、无欧赔、EV≤0，任一不过就否决，不许找理由放宽。
5. 日记只写球：场次/盘口/信号/买卖判断/资金/结算。空仓也必须记一行。

## 执行步骤

### 1. 机械层
- `POST http://127.0.0.1:9000/api/trigger/refresh` （抓盘+评分+赛果+快照，可能要几十秒）
- `POST http://127.0.0.1:9000/api/trigger/settle` （结算昨日真注/虚拟注）
- 两者都失败就在日记里如实记错误，不许假装有数据。

### 2. 扫盘
- `GET /api/day/{{DATE}}` → 关注 `summary`（total/scored/accPct）和 `table` 每一行：
  `num` / `match.home`+`match.away` / `match.matchTime` / `score.total` / `score.band` / `score.dir` / `score.odds` / `score.market` / `score.pred` / `result`
- 只关注 `score.total >= 40` 的行。

### 3. 对每个 ≥48 的信号过五门禁
对每个 `score.total >= 48` 的场次调 `GET /api/gate?date={{DATE}}&num=<场次号>`，读返回的：
- `r5`（是否在开赛前0.5~8h窗口内）
- `europe`（独立欧赔，null=无欧赔→永久否决实单）
- `m04`（EV门：`eligible` + `reason` + `jcEv` + `settleEv`）
- `score.band`（实单/加注档）

判定表：
| 情况 | 结论 |
|---|---|
| r5=false | 否决，死因「窗外 Xh」 |
| europe=null | 否决，死因「无欧赔」 |
| m04.eligible=false | 否决，死因「EV负 X%」 |
| band=58+ 且五门禁全过 | **列进「待人工确认·建议加注100」** |
| band=48-57 且五门禁全过 | **列进「待人工确认·建议实单50」** |
| 全部不过 | 记死因，不买 |

**注意 M-03**：quarter盘（如让-0.75/-1.25）的 `m04.settleEv` 系统性偏乐观，不许直接采信；整数盘才可参考。真要改投欧亚结算盘必须自己分拆（M>=2全赢、M==1半赢）。拿不准就否决。

### 4. 虚拟注
对当日 `score.total >= 40` 但**没下真注**的场次（以及≥48被否决的），每个都打一注虚拟注：
`POST /api/virtual` body: `{matchId, pick, odds, confidence, myView, analysis, reviewHook}`
- `pick`：用 `score.dir` 原样（如「主负」「客-2胜」「主+1胜」）——`settleVirtual` 靠这个字符串解析，让球必须带「让」字样
- `myView`：你的立场（跟着引擎方向或反着来，写清理由）
- `analysis`：≤40字，降水/模型/欧赔哪一维给了分
- `reviewHook`：赛后要验证什么（如「验证深盘退回是否正确」）
- 同场已有 open 注会自动 skip（幂等，放心调）

### 5. 写日记
`POST /api/diary` body: `{date: "{{DATE}}", type: "open", text: "..."}`，text 里必须包含：
- 抓了几场、评分几场、信息源有无报错
- **逐个≥48信号的去向表**（场次/分/方向@赔率 → 买了 / 窗外Xh / EV负X% / 无欧赔 / 待人工确认）
- 虚拟注开了几单
- 资金状态（`GET /api/summary` 的 cash）
