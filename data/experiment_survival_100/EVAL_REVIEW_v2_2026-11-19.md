# 评估复核 v2（2026-11-19）— 按第二批评审意见更正

> 保留 v1（`EVAL_REVIEW_2026-11-19.md`）不覆盖。本文只做更正与新增复核。
> 未触碰订单、账本、账户；未修改任何历史时间字段。

## 1. 术语更正

v1 中的「严格可用」「严格时间证据」「可证明的下界」**全部作废**，统一改为：

> **时间一致但采集时点未证实的条件样本**

原因：只证明了「赔率更新时间 ≤ 文件名时间」，不能证明「该文件在文件名所示时刻真实存在」。mtime 被整体改写，不能作为采集证据。

## 2. 报告与产物不一致的原因（已查）

v1 正文写「距开赛 30~4940 分钟、每场最多 6 个快照」，与附件 JSON 不符。现从**同一份最终 JSON 现算**：

| 项 | 值（v2 现算） |
|---|---|
| 进入主分析的比赛 | 43 |
| 每场快照数 | 最少 1 / 中位 3 / **最多 9** / 平均 3.21 |
| 距开赛分钟 | **最少 511 / 中位 1780 / 最多 2128** |
| 开赛日范围（北京） | 2026-08-24 ~ 2026-08-29 |
| 开赛前 60 分钟内样本 | **0** |
| 是否存在 T−30 样本 | **否** |

原因：v1 的正文数字来自更早一次运行（未加队 ID、未按比赛取单点前），后来重建数据集、改成「每场一个预设时点」后没有同步改正文。**物为准，正文错**。旧报告保留。

**重要结论**：这 43 场**没有一场接近临场**，最近 8.5 小时。**这批数据不能用于评估临场（T−30）机制**，只能用于「赛前较远时点」的描述性比较。

## 3. mtime 固定偏移（未定论）

| 偏移 | 文件数 |
|---|---|
| 28801 秒 | 22 |
| 28800 秒 | 4 |

正好 8 小时（+1 秒）。可能原因有三类，**目前无法区分**：
1. 批量复制/解压导致 mtime 被改写；
2. 时区处理错误（本地时间被当作 UTC 或反之）；
3. 抓取脚本写入后又被其他流程重写。

**不下结论**，记录为「未查明」。文件哈希已存（`snapshot_inventory.json` 每文件 `sha256_16`），可证明内容未变，但**不能证明采集时刻**。

## 4. Bootstrap 修复

v1 的伪随机数用普通浮点数做大整数乘法，精度丢失、短周期。已换成 `mulberry32`（`Math.imul`），并加自测：同种子同序列、前 20 万次无 4 元组重复、20 万次输出多样性 199,989。

重算（`match_level_report_v2.json`）：

| 方法 | 区间 | 说明 |
|---|---|---|
| 比赛级聚类 bootstrap | **[−0.0012, +0.1152]** | seed 20261119，20,000 次 |
| 日期块 bootstrap（敏感性） | **[+0.0117, +0.1279]** | 6 个日期块，seed 20261120，20,000 次 |

配对差均值 **+0.0564**（Brier3 模型 0.5721 vs 基线 0.5157）。

**边界**：日期块只有 6 个，块数太少；两种区间都**未调整同队重复**；比赛级独立假设只是近似。因此只能写「在这批条件样本上更差」，**不写显著**。

## 5. 防泄漏函数修复

`isLeakFree()` 原先只在 `NaN` 比较时漏判。现要求四个时间字段都必须是**有限数值**：

- `NaN`、`+Infinity`、`-Infinity`、`undefined`、`null`、字符串 → 一律拒绝并给出原因
- 边界：`predictMs = kickoffMs − 1` 通过

测试从 10 项增至 **12 项**，全过：

```
node app/tools/dataset.test.ts   → PASS 12, FAIL 0
node app/tools/rng.ts            → rng self-check OK
```

## 6. 新采集方案（冻结）

| 项 | 规则 |
|---|---|
| **主时点** | **T−35 至 T−30**，取窗口内**最新且采集成功**的一条 |
| 辅助时点 | T−25（单列「较晚观察」，**不并入 T−30**）；T−24h / T−6h / T−1h（±60min / ±20min） |
| 采样窗口 | 主窗口严格 5 分钟；窗口内无记录 → `missing`，**不插值、不补写** |
| 每条记录 | 真实采集时间（含时区）、源声称时间、两者差值、本机时钟状态、赛事 ID、开赛时间、独赢三项 + 让球线两侧 + 大小线两侧、原始内容 SHA-256、采集结果/失败原因 |
| 存储 | `YYYY-MM-DD/HHmmss_<hash8>.json`，**只增不改** |
| 评估 | 达到预先设定样本（≥300 场、≥3 个月）后，按**冻结**时点与切分评估一次；不得看测试集再换时点 |

哈希只能证明内容未变，**不单独证明采集时刻**；因此每条记录必须同时写入采集日志（进程启动时间、请求时刻、返回时刻）。
